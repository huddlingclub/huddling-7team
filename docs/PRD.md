# PRD | 얼음섬 🐧
### 월급이 녹는 펭귄 가계부 MVP

- 프로젝트명: 얼음섬
- 프로젝트 유형: 웹 기반 소비 기록 서비스
- 카테고리: 금융 / 재테크
- 작성일: 2026-11-14
- 개발 목표: 2시간 내 MVP 구현

---

## 01. 프로젝트 개요

### 한 줄 정의
얼음섬은 이번 달 월급을 빙하로, 사용자를 펭귄으로 표현하는 소비 압박형 가계부 웹 서비스다.

사용자가 지출을 기록할 때마다 빙하가 깨지고, 소비율이 높아질수록 바다사자가 다가온다. 월급을 모두 사용하면 바다사자가 펭귄을 잡아먹는다.

설치 없이 브라우저에서 사용할 수 있으며, 혼자 또는 둘이서 소비 기록을 관리할 수 있다.

### 제품 목표
- 소비에 따른 시각적 위기감으로 불필요한 지출 억제
- 숫자 중심 가계부보다 강한 소비 체감 경험
- 지출 기록을 반복하도록 유도
- 1인 및 2인 공유 가계부의 사용성 검증

### 핵심 콘셉트
"내가 돈을 쓸수록 빙하는 사라지고, 바다사자는 가까워진다."

---

## 02. 문제 정의

### 1인 사용자
- 숫자와 그래프만으로는 소비 규모가 직관적으로 느껴지지 않음
- 월급 대비 지출이 많아도 소비를 멈추기 어려움
- 가계부 기록이 단순 반복 작업처럼 느껴짐

### 2인 사용자
- 서로의 소비 현황을 바로 확인하기 어려움
- 월말에야 상대방의 지출을 파악하는 경우가 있음
- 소비 금액 비교가 갈등으로 이어질 수 있음

### 해결 방향
지출을 기록할 때마다 캐릭터가 위험해지는 시각적 피드백을 주어 소비에 대한 경각심을 높인다.

## 03. 핵심 기능

### ① 월 예산 설정
- 첫 실행 시 '혼자 / 둘이서' 모드 선택
- 사용자 이름 입력
- 이번 달 월급 또는 소비 목표 금액 직접 입력
- 금액 입력은 필수
- 설정 완료 시 온전한 빙하 위에 펭귄 등장
- 초기 빙하 크기는 설정한 금액을 기준으로 표현

### ② 지출 내역 기록
- 메인 화면의 '+ 지출 기록하기' 버튼 클릭
- 지출 금액, 내용, 날짜, 카테고리 입력
- 자주 쓰는 금액을 빠르게 입력하는 버튼 제공 (예: +1만 원, +3만 원)
- '저장하기' 클릭 시 누적 지출 금액 반영
- 저장 직후 빙하가 깨지는 애니메이션 실행
- 지출 내역 조회, 수정 및 삭제 가능

### ③ 소비율 계산
소비율(%) = 누적 지출 금액 ÷ 월 목표 금액 × 100

예시:
- 월 목표 금액: 2,000,000원
- 누적 지출 금액: 1,200,000원
- 현재 소비율: 60%
- 남은 금액: 800,000원

소비율은 지출 기록이 추가되거나 수정, 삭제될 때 자동으로 갱신한다.

### ④ 빙하 파괴 및 펭귄 반응

| 소비율 | 상태 | 시각적 변화 |
|---|---|---|
| 0~19% | 여유 | 온전한 빙하, 행복한 펭귄 |
| 20~39% | 여유 | 빙하에 작은 균열 발생 |
| 40~59% | 슬슬 | 균열 확대, 일부 빙하 붕괴, 펭귄 당황 |
| 60~79% | 위험 | 빙하 크기 감소, 바다사자 등장 및 접근 |
| 80~99% | 바다사자 접근 | 빙하 대부분 붕괴, 펭귄 일부 침수, 바다사자 코앞까지 접근 |
| 100% 이상 | 꿀꺽 | 빙하 완전 붕괴, 바다사자가 펭귄을 삼킴 |

- 캐릭터 상태는 5단계로 관리하며, 초기 '여유' 단계 안에서도 균열 정도를 구분한다.
- 각 지출에 따라 빙하 일부가 깨져 바다로 떨어진다.
- 소비율이 높아질수록 펭귄의 표정과 자세가 바뀐다.
- 100% 이후에도 지출 기록은 계속할 수 있다.
- 캐릭터 연출은 피나 상처가 없는 귀여운 만화 스타일로 제한한다.

※ 단계별 소비율과 파괴 정도는 초기 제안이며 개발 중 조정할 수 있다.

### ⑤ 소비 속도 예측
현재 누적 지출과 날짜를 기준으로 월 목표 금액이 소진될 예상 날짜를 계산한다.

예시:
- "지금 속도면 11월 19일에 바다사자에게 잡아먹혀요!"
- "월급의 62%를 사용했어요."

예상 날짜는 실제 지출 패턴에 따라 달라지는 추정값으로 표시한다.

### ⑥ 카테고리별 지출 확인
- 식비, 교통비, 쇼핑 등 지출 카테고리 선택
- 카테고리별 누적 지출 금액 확인
- 총 지출 중 카테고리별 비중 확인
- 가장 많이 지출한 카테고리 확인

복잡한 통계보다 어디에 돈을 많이 썼는지 빠르게 확인하는 데 집중한다.

### ⑦ 2인 공유 모드
- 각자 이름과 월급(목표 금액) 설정
- 사용자별 펭귄과 빙하 생성
- 동일한 공유 페이지에서 두 사람의 소비 현황 확인
- 상대방의 지출 기록 및 펭귄 상태 실시간 확인
- 소비 기록은 사용자별로 구분
- 비교 순위나 경쟁 요소는 제외

공유 권한과 상대방의 지출 메모 공개 범위는 구현 전 결정이 필요하다.

## 04. 주요 화면

### ① 초기 설정 화면
- 혼자 / 둘이서 선택
- 사용자 이름 입력
- 이번 달 월급 또는 목표 금액 입력
- '시작하기' 버튼

### ② 메인 화면
- 빙하 위에 서 있는 펭귄
- 수면 아래 바다사자
- 현재 소비율 (%)
- 누적 지출 금액 / 남은 금액
- 소비 속도 예측 메시지
- '+ 지출 기록하기' 버튼

### ③ 지출 입력 화면
- 지출 금액
- 지출 내용
- 날짜
- 카테고리
- 빠른 금액 입력 버튼
- '저장하기' 버튼

### ④ 지출 내역 화면
- 날짜별 지출 내역
- 지출 금액 및 카테고리 확인
- 기록 수정 및 삭제

### ⑤ 카테고리 화면
- 카테고리별 지출 금액
- 카테고리별 소비 비중
- 가장 많이 지출한 항목

## 05. 핵심 인터랙션

1. 사용자가 지출 내역을 입력한다.
2. '저장하기' 버튼을 누른다.
3. 현재 소비율을 계산한다.
4. 빙하에 균열이 생기고 일부가 떨어져 나간다.
5. 빙하 조각이 바다로 떨어지며 물결이 발생한다.
6. 소비율에 따라 바다사자가 가까워진다.
7. 펭귄의 표정과 자세가 변화한다.
8. 소비율과 남은 금액이 갱신된다.

100% 도달 시 특별 연출
- 빙하 완전 붕괴
- 펭귄이 바다에 빠짐
- 바다사자가 입을 크게 벌림
- 펭귄을 꿀꺽 삼키는 애니메이션
- 예산 소진 안내 메시지 표시

## 06. UX/UI 디자인 방향

- 귀여운 펭귄을 중심으로 한 캐릭터형 UI
- 수면 위 빙하와 수면 아래 바다사자가 함께 보이는 화면
- 소비율이 증가할수록 긴장감이 높아지는 연출
- 빙하 파괴 및 포식자 접근에 모션 적용
- 캐릭터 표정을 통한 소비 상태 전달
- 숫자나 그래프보다 캐릭터의 상황을 강조
- PC 및 모바일 브라우저에 맞는 반응형 화면
- 간단한 입력 구조와 최소한의 화면 전환

디자인 핵심: 소비 기록을 입력하는 행위가 곧 펭귄의 생존을 위협하는 경험이 되도록 설계한다.

---

## 07. 사용자 시나리오

1. 사용자가 서비스 링크에 접속한다.
2. 혼자 또는 둘이서 모드를 선택한다.
3. 이름과 한 달 월급을 입력한다.
4. 빙하 위에 서 있는 펭귄이 나타난다.
5. 소비 발생 시 '+ 지출 기록하기'를 누른다.
6. 금액과 카테고리를 입력하고 저장한다.
7. 빙하가 깨지고 펭귄의 표정이 변한다.
8. 소비율 60%부터 바다사자가 등장한다.
9. 80% 이상에서는 펭귄이 위험한 상황에 놓인다.
10. 100%에 도달하면 바다사자가 펭귄을 삼킨다.
11. 사용자는 카테고리 화면에서 지출을 확인한다.
12. 다음 달 1일에 새로운 빙하와 펭귄이 나타난다.

2인 모드에서는 각자의 소비 내역과 펭귄 상태를 공유 화면에서 함께 확인한다.

## 08. MVP 개발 범위

### 필수 기능
- 1인 월 예산 설정
- 지출 내역 입력, 수정, 삭제
- 누적 지출 및 소비율 계산
- 빙하 파괴 단계 구현
- 펭귄 표정 및 상태 변화
- 바다사자 등장, 접근 및 꿀꺽 연출
- 소비 데이터 저장
- 기본 반응형 웹 화면

### 확장 기능
- 2인 실시간 공유 및 동기화
- 소비 속도 기반 예산 소진 날짜 예측
- 카테고리별 소비 분석
- 월별 기록 관리
- 월말 소비 요약 공유

※ 2시간 MVP에서는 필수 기능을 먼저 구현하고, 실시간 공유 등은 개발 여건에 따라 범위를 조정한다.

## 09. 핵심 성과 지표

초기 데이터 측정 후 구체적인 목표를 설정한다.

1. 주간 활성 기록: 주 3일 이상 지출을 기록한 빙하 수 (North Star)
2. 기록 지속률: 4주 동안 기록을 유지한 사용자 비율
3. 소비 변화: 위험 단계 진입 전후 7일간 일평균 지출 비교
4. 공유 효과: 1인과 2인 사용자의 4주 기록 지속률 차이
5. 이탈률: 꿀꺽 연출 이후 7일간 기록이 없는 사용자 비율

## 10. 리스크 및 고려 사항

① 사용자 간 갈등
- 2인 모드에서 상대방의 소비를 비난하는 상황 발생 가능
- 순위 및 경쟁 표현 제외
- 지출 메모 공개 범위 설정 검토

② 소비 압박으로 인한 이탈
- 펭귄이 잡아먹힌 이후 기록 포기 가능
- 예산 소진 이후에도 지출 입력 허용
- 100% 이후 기록 지속률 확인

③ 실시간 공유 구현
- 동일한 페이지의 데이터 동기화 및 편집 권한 확인 필요
- 사용 환경과 개발 방식에 따른 구현 가능 범위 검토

④ 캐릭터 저작권
- 기존 레퍼런스 이미지를 그대로 사용하지 않음
- 오리지널 펭귄과 바다사자 캐릭터 사용

⑤ 서비스 차별성
- 복잡한 가계부 기능보다 빙하 파괴 인터랙션에 집중
- 캐릭터의 반응 및 월말 요약 공유 경험 강화

---

## 11. 월별 운영 규칙

- 한 달 단위로 예산 및 지출 계산
- 매월 1일 새로운 빙하 생성
- 월이 바뀌면 해당 월의 소비율은 0%부터 시작
- 이전 달 지출 내역은 별도로 보관
- 월급 또는 목표 금액은 사용자가 직접 설정

---

## 12. 최종 목표

얼음섬은 복잡한 금융 관리 서비스가 아니다.

사용자가 소비 내역을 직접 기록하고, 그때마다 빙하가 깨지고 바다사자가 다가오는 모습을 보여주는 소비 압박형 캐릭터 가계부다.

핵심 경험은 단 하나다.

"돈을 쓰는 순간, 내 펭귄이 위험해진다."
